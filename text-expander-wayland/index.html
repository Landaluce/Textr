Text expansion that works in native Wayland apps

Most expanders hook X11, so on a Wayland session they only see XWayland windows and fire nothing in your actual apps. Textr reads keyboard events straight from /dev/input with evdev and types the expansion through ydotool — while also keeping the X11 path working.

The two halves of the problem

Capture: reading keys without X11

Wayland deliberately doesn't let apps observe keystrokes. X11 tools like pynput therefore only ever see XWayland clients. Textr's Wayland backend opens the raw event devices instead:

sudo usermod -aG input "$USER"   # then log out and back in
# /dev/input/event* now readable; Textr's evdev listener attaches to them

If evdev isn't available (no python-evdev, or no permission on the devices), Textr falls back to pynput and prints why — you get XWayland-only expansion rather than silence.

Output: typing without a clipboard

On Wayland, unmapped paste shortcuts aren't reliable, so expansions are typed with ydotool, which speaks the kernel's uinput layer. Start the daemon once:

sudo systemctl enable --now ydotool.service
# or: ydotoold &

You can also choose Human Typing mode on X11, which types character by character through the same mechanism instead of pasting.

Keyboard layouts

evdev reports keycodes, not characters — 2 is just a position on the board. Textr maps keycodes through a layout table before matching triggers, and AltGr characters are included.

LayoutSettingExample: @
US"layout": "us"Shift + 2
UK"layout": "uk"Shift + '
German"layout": "de"AltGr + Q
French"layout": "fr"AltGr + 0
Spanish"layout": "es"AltGr + 2

Set it in Settings → Keyboard layout. Tables are best-effort for the common variants; LAYOUTS in input_wayland.py is a plain dict if yours differs.

When it doesn't fire, diagnose instead of guessing

textr-diag (or python3 -m diag from a checkout) reports the session type, every input device with its permissions, whether Python packages are present, and whether ydotool is available and running:

textr-diag                 # environment report
textr-diag --listen 5      # press keys for 5s, see keycode -> character
textr-diag --test-type     # type a test string through ydotool

The --listen output is the fastest way to spot a wrong layout or a key that never arrives: you see the exact characters Textr will match against your triggers.

What Textr doesn't do

  • Five layouts only (us, uk, de, fr, es) — an exotic layout or a remapped key needs a new entry in the table.
  • The global quick-insert hotkey is X11-only; on Wayland you insert from the manager window or tray.
  • Wayland needs setup you can't skip: ydotool running, plus input group membership for capture.
  • No sandboxed builds — a Flatpak or Snap would not get raw device access, so run the binary or the source install.
